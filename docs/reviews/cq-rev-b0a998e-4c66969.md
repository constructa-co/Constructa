## Commit `b0a998e` — profile / case-studies fail-closed

### What changed

- `profile/page.tsx` and `case-studies/page.tsx` now treat `error || !data` from `.single()` as **unconfirmed** reads: show a `role="alert"` panel and **do not** mount `ProfileForm` / `CaseStudiesClient` (or the case library panel when the profile read failed).
- `unstable_rethrow(error)` in `catch` preserves Next.js redirect/navigation throws before mapping other exceptions to unavailable UI.
- New Vitest SSR markup tests: `phase1b-profile-read-outcomes.test.tsx`, `phase1b-case-studies-read-outcomes.test.tsx`.

### Correctness

- **Sound fail-closed rule:** Partial rows with a concurrent `error` (e.g. RLS/permission) no longer populate empty or stale editors — aligns with A086/A091 intent.
- **Case library gating:** `sessionReader(...).library` is skipped when `profileUnavailable`, avoiding extra reads and inconsistent UI when the profile row is not confirmed.
- **Success path preserved:** Confirmed `data` still passes `case_studies` into the client (with a typed cast on case-studies only).

### Bugs / gaps

| Severity | Item |
|----------|------|
| Non-blocking | **Error text in UI:** `profileDetail` surfaces raw Supabase `error.message` (and transport errors) to the signed-in user. Useful for support; minor information disclosure if messages ever include internal codes/paths. |
| Non-blocking | **Missing row UX:** `null` data + `null` error → copy `"Profile not found."` — correct fail-closed, but no guided path to create a profile (pre-existing product gap, not introduced here). |
| Non-blocking | **Library failures untested:** When profile succeeds and `caseLibraryEnabled()` is true, a failing `library()` call is not covered by the new tests (still handled by existing case-library boundary tests per handoff). |
| Non-blocking | **`unstable_rethrow`:** Tests mock rethrow only for `NEXT_*` messages; real redirect propagation is assumed correct from Next.js docs. |

### Risky patterns

- None blocking. The `profile!` non-null assertion after `profileUnavailable` guard is safe.

- `APPROVED_GENERATION` becomes lazy getters calling `deepSeekQaApproval()` per feature when provider is configured; caps/prices/ref documented in source.

- **Defense in depth:** `ready: onQaPreview` re-checked at `send` time; env flip to production after reservation releases ledger (`not_sent` test).
- **No OpenAI fallback** after DeepSeek failure (explicit test).
- **Ledger still gates runtime:** `jobAssistantAvailable` remains false without `covers()` — matches “source config only until SQL/settings enabled” narrative.
